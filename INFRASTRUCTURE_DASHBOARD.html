Data Workflows

1️⃣ Kubernetes Cluster Setup Workflow

Flow: Ansible → Control Plane Generation → Token Distribution → Worker Nodes Join

Control plane generates join tokens and certificate keys automatically. Tokens are distributed via Ansible facts to workers. Workers validate tokens and join the cluster. No manual token management required.

  • Ansible creates control plane (203.0.113.42)
  • Generate kubeadm join tokens and cert keys
  • Store tokens in Ansible hostvars
  • Serial execution: workers join sequentially
  • Cluster validation after all nodes join

2️⃣ Kafka Cluster ID Distribution Workflow

Flow: Ansible → Leader Election → UUID Generation → Cluster ID Distribution

First node in inventory (203.0.113.70) becomes leader and generates UUID-based cluster ID. ID is automatically copied to follower nodes (.71, .72). All nodes configured with same cluster ID for KRaft quorum coordination.

  • Ansible selects first host as leader
  • Leader generates UUID cluster ID
  • Cluster ID written to /opt/kafka/cluster.id
  • Distributed to all followers via delegation
  • Controller quorum pre-configured

3️⃣ Application to Kafka Event Stream

Flow: Jenkins/K8s Apps → Kafka Topics → Event Processing

Applications running in Kubernetes or Jenkins publish events to Kafka topics. Kafka brokers coordinate via KRaft consensus. Events are streamed to subscribed consumers and forwarded to ELK Stack for logging.

  • Applications produce events to Kafka topics
  • Kafka brokers maintain consistent log
  • Consumer groups process events
  • Logstash consumes Kafka topics
  • Elasticsearch stores normalized data

4️⃣ Jenkins CI/CD Build Pipeline

Flow: Jenkins (203.0.113.42) → Maven Builds → Artifact Publishing → K8s Deployment

Jenkins polls source repositories for changes. Maven executes builds and produces artifacts. Artifacts are pushed to container registry or K8s-native storage. K8s deploys updated container images from artifacts.

  • Jenkins receives build triggers
  • Maven compiles and packages code
  • Tests executed during build
  • Artifacts stored (Docker images, JARs)
  • K8s deployment controllers pull and deploy

5️⃣ Unified Logging via ELK Stack

Flow: All Components → Logstash → Elasticsearch → Kibana Visualization

Logs from Kubernetes, Kafka, Jenkins, and applications are shipped to Logstash. Logstash parses, enriches, and normalizes log data. Elasticsearch stores indexed logs. Kibana provides real-time searching and visualization.

  • Pod logs captured via K8s logging agents
  • Kafka broker logs streamed to Logstash
  • Jenkins build logs forwarded
  • Logstash filters and transforms data
  • Elasticsearch indexes with configurable retention
  • Kibana dashboards for monitoring and analysis

6️⃣ Metrics Collection via Victoria Metrics

Flow: Application Metrics → Victoria Metrics → Grafana Dashboards

Prometheus-compatible metrics are scraped from all components (K8s, Kafka, Jenkins). Victoria Metrics stores time-series data efficiently with long-term retention (12 months default). Grafana visualizes metrics in customizable dashboards.

  • K8s kubelet exposes metrics
  • Kafka brokers publish JMX metrics
  • Jenkins exposes build/system metrics
  • Prometheus scraper collects metrics
  • Victoria Metrics stores long-term data
  • Grafana creates correlation dashboards
